# Как помочь проекту

Спасибо, что заглянули. Баг-репорты, идеи и пулл-реквесты приветствуются.

## Сообщить об ошибке

Откройте [issue](https://github.com/chelond/tonearm/issues/new/choose) по шаблону «Ошибка». Помогут:

- версия Tonearm (Настройки → Обновления) и ОС;
- какой плеер включён: встроенный или Soloist;
- журнал с `RUST_LOG=debug`. На Windows он лежит в `%LOCALAPPDATA%\tonearm\data\tonearm.log`.

Перед отправкой уберите из журнала имя пользователя и всё, что похоже на токен.

## Собрать и проверить

Как поставить зависимости для своей ОС, написано в [README](README.md#сборка-из-исходников). Перед пулл-реквестом:

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Интерфейс можно смотреть без аккаунта: `TONEARM_UI_PREVIEW=home cargo run` (список экранов в README).

## Устройство кода

```
crates/core    сессия, вход, librespot, Soloist, медиатека, кэш, обновления
crates/player  очередь, shuffle/repeat, громкость, перемотка, события плеера
crates/app     интерфейс на Slint
```

Интерфейс общается с `core` и `player` только через каналы команд и событий, бизнес-логики в нём нет.
Сетевые ошибки не должны ронять приложение: покажите понятное сообщение и попробуйте снова.
Заметки о решениях и ограничениях API: [docs/PLAN.md](docs/PLAN.md).

## Правила

- Токены, ключи и Client ID никогда не попадают в код, файлы репозитория и журналы.
- Никаких логотипов и фирменного оформления Spotify.
- Одна задача на пулл-реквест; заметное для пользователя изменение добавьте в раздел
  `[Unreleased]` в [CHANGELOG.md](CHANGELOG.md).

## Выпуск версии

1. Перенести `[Unreleased]` в CHANGELOG под новую версию.
2. Поднять `version` в `Cargo.toml` и `pkgver` в `packaging/arch/PKGBUILD`, закоммитить.
3. Поставить тег `vX.Y.Z` и запушить. CI соберёт и подпишет файлы и опубликует релиз с заметками
   из CHANGELOG. Для подписи нужен секрет `UPDATE_SIGNING_KEY`.
