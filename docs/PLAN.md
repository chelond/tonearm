# План разработки Tonearm

Рабочее название: **Tonearm** (легко поменять: имя пакета, `.desktop`, заголовок окна).
Данные сверены 17.11.2026 по crates.io и исходникам крейтов.

## Ключевые риски и решения

1. **Ограничения Web API (февраль 2026).** Для новых Client ID в Development Mode: владелец приложения должен иметь Premium,
   не больше 5 пользователей на Client ID, поиск отдаёт максимум 10 результатов за запрос, удалены пакетные
   `GET /tracks|/albums|/artists`, `browse/new-releases`, `browse/categories`, `artists/{id}/top-tracks`, `users/{id}/playlists`;
   `/playlists/{id}/tracks` стал `/playlists/{id}/items`, а содержимое отдаётся **только для своих или совместных плейлистов**;
   сохранение в медиатеку перенесено на `PUT/DELETE /me/library`.
   **Решение:** гибрид. Web API для поиска, списка моих плейлистов и Liked Songs; метаданные плейлистов, альбомов,
   артистов (включая топ-треки) и треков берём через `librespot-metadata` (внутренний протокол), он этих ограничений не имеет.
   Клиентский код Web API пишем сразу под новые эндпоинты.
2. **Токен для Web API.** `Session::token_provider().get_token(scopes)` в librespot-core 0.8 есть, но токен выдаётся
   на внутренний client id и на практике упирается в лимиты (429). **Решение:** пробуем токен сессии, при 401/403/429
   переключаемся на собственный Client ID (PKCE через `librespot-oauth`), Client ID в `config.toml`.
3. **Авторизация librespot.** Вход через `librespot-oauth` (`OAuthClientBuilder::new(client_id, redirect_uri, scopes).open_in_browser()`,
   `get_access_token_async()`), затем `Session::connect` с `Credentials::with_access_token`, после чего сохраняем
   reusable credentials сессии в keyring для автологина. Refresh-токены тоже только в keyring.
4. **Память UI.** Замер под Xvfb: программный рендерер Slint ~21 МБ RSS, femtovg (OpenGL) и skia ~138 МБ.
   Программный рендерер выбран по умолчанию; на реальной видеокарте перемерим на этапе 9.
5. **souvlaki на Windows** требует HWND окна: возьмём через `raw-window-handle` из Slint (фича `raw-window-handle-06`).
6. **Системные зависимости.** Сейчас: fontconfig, freetype, libxkbcommon(-x11), wayland, libX11 и др. (подгружаются через dlopen).
   Добавятся: alsa-lib, libpulse (librespot), dbus (souvlaki, Secret Service). TLS: по возможности rustls, чтобы не тянуть openssl.

## Заметки по этапу 2

- Вход: `librespot-oauth` с client id самого librespot (`SessionConfig::default().client_id`, в нашем коде не захардкожен),
  redirect `http://127.0.0.1:8898/login`. Синхронный `get_access_token()` в `spawn_blocking`: его слушатель блокирующий.
  Отмена: запрос без `code` на 8898 завершает слушатель.
- После `Session::connect` сохраняем `username` + `auth_data` как `AUTHENTICATION_STORED_SPOTIFY_CREDENTIALS` (JSON) в keyring,
  запись `tonearm / librespot-credentials`. Файловый кэш librespot не используем: он хранит учётные данные открытым текстом.
- Хранилище на Linux (решение от 19.11.2026): Secret Service, а если его нет, то зашифрованный файл
  `~/.local/share/tonearm/secrets/*.bin` (0600, каталог 0700, атомарная запись). ChaCha20-Poly1305 из `ring` (уже в дереве через rustls),
  ключ HKDF-SHA256 от `/etc/machine-id` + uid со случайной солью, AAD связывает файл с именем записи. При появлении Secret Service
  вход переносится туда, файл удаляется. Защищает от копирования файла, но не от процессов того же пользователя.
- Ошибки: `PermissionDenied` от librespot → данные отклонены, удаляем и просим войти; остальное → повтор через 2, 4, 8, 16, 30, 60 с.
  Раз в 5 с проверяем `Session::is_invalid()` и переподключаемся.
- Логи: цели `librespot_oauth` и `librespot_core` ограничены уровнями info/debug, потому что на trace они печатают ответы с токенами.
  Тип `Secret` скрывает значение в `Debug`.
- Сборка: `vergen` закреплён на 9.0.6 в `Cargo.lock`. С 9.1 у build-скрипта librespot-core 0.8.0 конфликт версий `vergen-lib`.
  Не делать `cargo update` без `--precise` для него.

## Заметки по этапу 3

- Сессия передаётся из core в player через `watch::channel<Option<Session>>`: core публикует её при входе и `None` при выходе/обрыве.
  UI сессию не видит.
- `librespot-playback` с `rodio-backend` (rodio 0.21 / cpal 0.16), микшер `SoftMixer`, битрейт 320, позиция каждые 500 мс
  (`position_update_interval`). События librespot фильтруются по `play_request_id`, чтобы не мигали устаревшие.
- librespot делает `unwrap()` при открытии аудиоустройства. Сборщик sink обёрнут в `catch_unwind` и при сбое отдаёт
  `NoDeviceSink`: librespot ставит паузу, UI показывает сообщение, следующее «Играть» пересоздаёт плеер.
  Поэтому из release-профиля убран `panic = "abort"`.
- Ссылки `open.spotify.com/track/…` (в т.ч. `intl-xx/` и `?si=`) приводятся к `spotify:track:…`. Альбомы и плейлисты
  пока не играются: нужна очередь (этап 6).
- Обложки в панели плеера появятся на этапе 4 вместе с кэшем изображений.

## Заметки по этапу 4

- Web API (`crates/core/src/library/webapi.rs`) работает на токене сессии (`token_provider`). Под лимиты Dev Mode 2026:
  `/playlists/{id}/items` с откатом на `/tracks`, поле `item` с откатом на `track`, 429 повторяется до 3 раз с учётом
  `Retry-After` (не больше 30 с). Свой Client ID как запасной путь остаётся на этап 9.
- Страница артиста целиком из `librespot-metadata`: 10 популярных треков и дискография по годам.
- Главная: «Продолжить» (играющий трек, единственная цветная обложка) и «Недавно слушали» из сохранённых альбомов.
  Рекомендаций и `browse/*` нет, их убрали из Web API.
- Обложки: `CoverCache` качает только с `*.scdn.co` / `*.spotifycdn.com`, хранит файлы по SHA-256 URL в кэше ОС,
  чистит старые по лимиту размера. Ч/б версия делается в Rust при загрузке, в модель уходит ч/б, играющему — цветная.
- Списки треков через `ListView` (виртуализация), страница переключается с отменой предыдущей загрузки.
- Интерфейс по концепции «Пульт» (`docs/DESIGN.md`, `crates/app/ui/theme.slint`). Шрифты Inter, Inter Display,
  JetBrains Mono (OFL) встроены в бинарник. Замер release под Xvfb: ~31 МБ RSS.

## Заметки по этапу 5

- `GET /search` сверен с changelog февраля 2026: `limit` не больше 10 (по умолчанию 5), дальше страницы через `offset`;
  типы track, album, artist, playlist остались. У артистов больше нет `popularity`/`followers`, поэтому подзаголовок
  артиста — первый жанр.
- Один запрос `type=track,album,artist,playlist&limit=10` даёт все вкладки сразу: переключение вкладок без запросов.
  «Ещё 10» на вкладке запрашивает только этот тип со смещением. Счётчик `10+` значит, что у Spotify есть ещё.
- Набор текста гасится паузой 300 мс в сервисе библиотеки, новый запрос отменяет предыдущий,
  ответы на устаревший запрос UI отбрасывает по тексту запроса. В элементах ответа бывают `null`, они пропускаются.
- «Лучший результат» Web API не отдаёт: эвристика `SearchResults::best` (точное совпадение исполнителя или альбома,
  потом по началу имени, потом альбом первого трека).
- Ссылки `open.spotify.com/...` и URI `spotify:...` в поле поиска не ищутся: Enter включает трек или открывает
  альбом, плейлист, исполнителя (`tonearm_player::uri::parse_link`).

## Заметки по этапу 6

- Очередь (`crates/player/src/queue.rs`) — чистая логика с тестами: контекст (плейлист, альбом, результаты поиска)
  в порядке воспроизведения плюс треки, добавленные вручную. Ручные играют сразу после текущего, позиция
  в контексте при этом сохраняется.
- Shuffle перемешивает всё, кроме текущего трека (он остаётся первым); выключение возвращает порядок альбома
  с текущего места. Repeat: выкл → всё → один. «Один» действует только на автопереход: ⏭ всё равно переключает.
- ⏮ в первые 3 с переходит к предыдущему, позже перематывает в начало.
- Gapless: по `TimeToPreloadNextTrack` librespot заранее грузит следующий трек (`Player::preload`).
- Недоступные треки пропускаются, не больше 10 подряд, чтобы repeat-all по «мёртвому» плейлисту не крутился вечно.
- Двойной клик по строке делает всю страницу контекстом и начинает с этой строки; недоступные треки в контекст не входят.
- Правый клик по треку: «В очередь», «К исполнителю», «К альбому» (+ «В любимые» с этапа 9; «В плейлист» не сделан). Горячие клавиши и медиаклавиши сделаны на этапе 7.

## Заметки по этапу 7

- souvlaki 0.9.3 с фичей `use_zbus`: MPRIS на чистом Rust, без libdbus (zbus уже был в дереве через keyring).
  На Windows SMTC получает HWND окна через `raw-window-handle` (фича Slint `raw-window-handle-06`), поэтому
  контролы создаются после старта цикла событий. **Сборка под Windows здесь не проверялась**, нужен CI.
- Из ОС приходят Play/Pause/Toggle/Next/Previous/Seek/SetPosition/SetVolume/OpenUri/Raise/Quit; всё уходит в канал плеера,
  Raise/Quit — в UI. Позиция в MPRIS обновляется только при смене состояния и скачках (перемотка): клиенты сами
  интерполируют, лишние сигналы раз в 500 мс не нужны.
- Проверено в песочнице: `org.mpris.MediaPlayer2.tonearm` появляется на сессионной шине, Metadata/PlaybackStatus/Identity
  читаются, вызов `Player.Next` доходит до плеера.
- Уведомление: прямой вызов `org.freedesktop.Notifications.Notify` через zbus (без notify-rust), заменяет предыдущее
  (`replaces_id`), только когда окно не в фокусе (winit через `slint::winit_030`). На Windows вместо тоста — оверлей SMTC.
- Трей отложен: на Linux он требует StatusNotifierItem и отдельной реализации, пользы мало при MPRIS-виджетах.
- Замер release под Xvfb после этапа 7: ~33 МБ RSS.

## Заметки по этапу 8

- Сторона пульта: `crates/core/src/connect.rs` через Web API `/me/player` (в changelog февраля 2026 эти эндпоинты
  в разделе «still available»). Токен сессии запрашивается со scope `user-read-playback-state`,
  `user-modify-playback-state`.
- Выбор устройства в деке: очередь отсюда (текущий трек + дальше, окно до 100 URI) уходит на устройство через
  `PUT /me/player/play` с позицией, локальный плеер ставится на паузу. Если здесь ничего не играло — `PUT /me/player`
  (transfer). Пока играет удалённое устройство, ▶/⏮/⏭/перемотка/громкость/двойной клик по треку и медиаклавиши
  идут туда; состояние опрашивается раз в 3 с, между опросами шкала двигается сама.
- «Этот компьютер» возвращает воспроизведение: удалённое устройство ставится на паузу, трек продолжается здесь с той же
  секунды (`PlayerCommand::PlayAt`, внутри текущей очереди, если трек в ней есть).
- **Tonearm не виден как Connect-устройство** в приложении на телефоне. Для этого нужен `Spirc` из librespot-connect:
  он сам управляет плеером и очередью, то есть наша очередь (этап 6) должна стать его очередью. Это отдельная
  крупная задача, отложена.
- Перемешивание и повтор на удалённом устройстве не переключаются (только локально).

## Заметки по этапу 9

- Настройки в `config.toml` (`crates/core/src/config.rs`): `[audio] bitrate/normalisation/gapless/device`,
  `[cache] max_size_mb`, `[ui] notifications`. Битые значения и неизвестные ключи не мешают запуску. Запись атомарная
  (временный файл + rename). Токенов в файле нет.
- Экран настроек по макету 08 сохраняет сразу. Звук применяется через `PlayerCommand::Configure`: плеер librespot
  пересоздаётся при запуске следующего трека (качество, нормализация, gapless задаются только при создании). Аудиовыход перечисляется через cpal; если выбранного устройства нет, звук идёт в системное по умолчанию.
- Кэш обложек: лимит меняется на лету, лишнее удаляется сразу, «Очистить» стирает всё.
- «В любимые» / «Убрать из любимых» (на странице «Любимые треки») в меню правого клика: `PUT/DELETE /me/library`
  (так в changelog февраля 2026: `/me/tracks` на запись удалены). Scope `user-library-modify` добавлен к токену сессии.
  **Не проверено на настоящем аккаунте**: токен выдаётся под Client ID официального клиента, Spotify может не дать права
  на запись. Тогда приложение покажет понятную ошибку, а запасной путь — свой Client ID из `config.toml`.
- Свой Client ID как запасной путь для Web API пока не подключён: ждём реальных 403/429 с токеном сессии.
- MSI: `crates/app/wix/main.wxs` (WiX v3, cargo-wix), см. `packaging/windows/README.md`. На Windows не собирался.
- Debug-сборки: зависимости без отладочной информации (`[profile.dev.package."*"] debug = false`), `target/` с 25 до 3 ГБ.
- Память: release под Xvfb после этапа 9 — ~34 МБ RSS (цель < 100 МБ).

## Архитектура

```
app (Slint UI, главный поток)
  │ mpsc<Command> ▼          ▲ mpsc<Event> + slint::invoke_from_event_loop
core (tokio runtime): Session, Auth, WebApi, Metadata, Cache
  │
player: Queue, Shuffle/Repeat, Volume, Seek → librespot Player
```

UI не содержит бизнес-логики: только отправляет `Command` и отображает `Event`. Сетевые ошибки превращаются в
`Event::Error { message, retrying }`, core переподключается с экспоненциальной задержкой.
